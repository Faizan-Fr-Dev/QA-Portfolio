## 📌 Project Overview

This project demonstrates practical experience in **manual software testing** of the OpenCart e-commerce application. The objective was to validate key application features, execute test cases, identify unexpected behavior, document defects, and evaluate the overall testing results.

The project follows a structured QA workflow, from test planning and scenario design to test execution, defect reporting, and test closure.

## 🎯 Project Objectives

* Validate important e-commerce workflows and application functionality.
* Design and execute structured manual test cases.
* Compare actual results against expected results.
* Document defects with reproduction steps and supporting details.
* Track passed, failed, and blocked test executions.
* Prepare professional software testing documentation.

## 🧪 Testing Scope

| Module              | Features Covered                                     |
| ------------------- | ---------------------------------------------------- |
| User Management     | Registration, Login, Logout, Password Recovery       |
| Account Management  | Account Information, Password, Address Book          |
| Product Features    | Search, Product Details, Product Comparison, Reviews |
| Shopping            | Wishlist, Shopping Cart, Quantity Validation         |
| Checkout            | Checkout workflow and related test conditions        |
| Orders              | Order History, Returns, and related account features |
| Additional Features | Affiliate Account, Newsletter, Gift Certificates     |
| User Interface      | Header, Footer, Navigation Menus, Currency Change    |

## 📊 Test Execution Summary

| Metric                |     Result |
| :-------------------- | ---------: |
| Total Test Executions |    **491** |
| ✅ Passed              |    **466** |
| ❌ Failed              |     **11** |
| ⏸️ Blocked            |     **14** |
| Pass Rate             | **94.91%** |

### Execution Results

* **Passed:** 466 executions completed successfully.
* **Failed:** 11 executions did not meet their expected results and were documented for investigation.
* **Blocked:** 14 executions could not be completed under the available test conditions.

> **Note:** These figures represent recorded test executions, not necessarily 491 unique test cases. Blocked tests require their prerequisites to be resolved before execution can be completed.

## 🐞 Defect Reporting

A total of **11 defect reports** were documented during the testing activities.

The reported issues covered areas such as:

* Registration and validation behavior
* Login and session handling
* Product search and search relevance
* Keyboard navigation and accessibility-related behavior
* Invalid quantity validation in shopping workflows

Each defect report includes relevant information such as:

* Bug ID and summary
* Preconditions and steps to reproduce
* Test data
* Expected result
* Actual result
* Priority and status
* Related test case reference

## ⚙️ Testing Approach

The project followed a structured manual testing process:

1. **Planning:** Reviewed the application scope and prepared the test plan.
2. **Scenario Design:** Identified important application workflows and features.
3. **Test Case Design:** Prepared test cases with steps and expected results.
4. **Execution:** Executed test cases and recorded observed results.
5. **Defect Reporting:** Documented failed behavior and linked defects to relevant test cases.
6. **Closure:** Summarized execution outcomes, blockers, limitations, and recommended follow-up activities.
